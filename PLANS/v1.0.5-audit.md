## 🎯 目标

修复审计发现的契约层面问题，分两层：
- **P1**：9 项前后端契约不匹配（前端调用了后端不存在/路径不一致的端点）—— 用户可感知的功能性 bug
- **P0**：错误/认证契约归一化 —— 为后续 P2/P3 打地基，但不触碰 REST 路由迁移

### 审计交叉验证结论（3 个独立 Explore agent 已核实）

| 审计声明 | 验证结论 |
|---|---|
| 9 项契约不匹配中 8 项属实 | ✅ 真实 |
| `/tags/batch-delete` 不匹配 | ❌ **误报**：后端 `tag_management.py:665` 确有该端点，**不动** |
| `/tracker-messages/statistics` 不匹配 | ✅ 真实，根因是 `tracker_messages.py:271` 的 `get_statistics` **漏挂 `@router.get` 装饰器**（orphan function） |
| `tag_management.py` 的 `{"success","message"}` 字典绕过 CommonResponse | ⚠️ **表述错误**：是私有 helper 内部返回值，非 HTTP 响应，**降级不改** |
| 后端认证双模式 / HTTP 500 双模式 / RPC 风格路径 | ✅ 全部真实 |
| 前端 ApiError 缺失 / any 滥用 / 双 header / Vuex 风格分裂 | ✅ 全部真实 |

## 📋 任务清单与实施顺序

> **顺序依据**：3 个独立审查 agent 一致建议——P0-3（异常处理器）最先做兜底，P0-1（前端归一化）在 P0-2（后端 401）之前避免破损窗口，P0-2c（认证基础设施）先于 P0-2a（批量迁移）避免 user_id 断链。

### Phase 0: P0-3 后端全局异常处理器（最先做）

- [ ] **P0-3.1** 在 `backend/app/` 新建异常处理器模块，注册两个 handler：
  - `@app.exception_handler(Exception)`：未捕获异常 → HTTP 500 + `CommonResponse(status="error", code="500", msg=...)`
  - `@app.exception_handler(HTTPException)`：归一化手写 HTTPException 的 detail（纯字符串 / CommonResponse dict / 其他），统一返回 `{code, msg}` 结构
- [ ] **P0-3.2** 在 `factory.py:create_app()` 注册处理器
- [ ] **P0-3.3** 跑全量 pytest 确保不破坏现有行为
- **不动**：endpoint 内手写的 `code="500"` 本期不批量改（留给后续），仅保证漏网 `raise` 被兜底

### Phase 1: P0-1 前端 request.ts ApiError 归一化

- [ ] **P0-1.1** 新建 `ApiError` 类（`extends Error`，含 `code/httpStatus/rawResponse/rawRequest`，加兼容 getter `msg`/`response`）
- [ ] **P0-1.2** 重写 response 拦截器：
  - 成功码白名单 `code in {'200','206','207'}` 才 return res
  - 业务错误（其他 code）→ ApiError
  - HTTP 错误 → 4 分支解包判定树（string / envelope dict / 422 array / fallback）
  - blob 请求错误短路（不解包 Blob body）
  - 登录接口豁免（`url.includes('/login')` + code=401 只 reject 不跳转）
- [ ] **P0-1.3** 双 header 收敛：只发 `Authorization: Bearer`，移除 `x-access-token`
- [ ] **P0-1.4** 新建 jest 单测覆盖 3 种响应归一化
- [ ] **P0-1.5** `npm run lint` 通过

# 故障排查

遇到问题时先记录产品版本、部署方式、发生时间和相关日志，再按下面的路径检查。不要直接删除数据库或整个 `data` 目录。

## 页面打不开或显示 502

1. `docker compose ps` 确认 frontend 和 backend 都在运行。
2. 查看 `docker compose logs --tail=200 backend`，确认后端是否通过 `/health/ready`。
3. 如果后端反复重启，检查 `DEV`、`SECRET_KEY`、`ALLOWED_HOSTS` 和配置目录权限。
4. 如果只有前端是旧版本，重新构建前端镜像并清理浏览器/PWA 缓存。

## 后端启动停在迁移阶段

迁移失败时保留原始日志和数据库备份，确认配置目录可写、磁盘空间足够，并检查是否有其他进程占用 SQLite 文件。不要用空数据库替换现有库来“绕过”迁移。

## 下载器连接失败

- 从后端所在环境测试下载器地址，而不是只从浏览器测试。
- 检查 qBittorrent 或 Transmission 的 Web API、端口、HTTPS 和认证设置。
- 确认地址没有使用手机或容器内的错误 `localhost`。
- 查看下载器能力检查结果和后端结构化错误码；不要把日志中的 token 或密码复制到工单。

## 登录、TOTP 或会话异常

确认服务器时间、手机时间和 TOTP 时间窗口基本一致。修改密码后旧设备会话失效，需要重新登录。多标签页状态异常时先刷新所有标签页，再查看浏览器控制台和后端认证日志。

## 孤儿文件扫描或删除异常

先确认扫描根路径、下载器路径映射和权限。查看置信度、忽视名单、预览结果和隔离区记录；对硬链接、副本和网络路径保持谨慎。Android 本机服务端模式可能按能力矩阵禁用文件系统操作。

## Android 无法连接本机服务

查看向导显示的阶段：目录准备、迁移、导入、绑定或健康检查。32 位设备不支持本机服务端模式；LAN 访问需要显式打开开关，并使用手机可达的地址和动态端口。

## 需要提交诊断信息时

优先提交版本、健康接口结果、去敏后的日志片段和复现步骤。BtDeck 提供 `/health/diagnosis` 诊断导出时，可先检查并移除域名、用户名、路径和密钥等敏感内容，再分享文件。

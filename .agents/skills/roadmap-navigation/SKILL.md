# Roadmap Navigation（roadmap 导航）

## 目的

以最小 token 消耗，通过 `docs/roadmap/` 代码路线图定位 BTDeck 项目中任意功能/模块的源文件。roadmap 是"对源码结构的有证据索引"，按三层渐进式披露。

## 导航决策流程

遇到"定位代码"任务时按序执行，**命中即停，不逐层读完**：

1. **Grep 定位（默认首选）**：在 `docs/roadmap/` 目录下用 `Grep -i <功能关键词>` 搜索，命中行即含"模块名 + 文件 + 一句话职责"。禁止直接 `Read` 整份 README。
   - 实测：`Grep -i orphan docs/roadmap/` 命中 41 行 ≈ **2,047 token**；`Read` 5 份 README 全文 ≈ **13,025 token**，省 **84%**。
2. **功能域速查（第一层直达）**：读根 `docs/roadmap/README.md` 的"功能域速查"表，按功能词（含中英文检索词）直接找到源文件路径，跳到目标文件。
3. **按需选择层级**：
   - 只需文件路径 → 停在第一层（根 README 功能域速查 / 分支说明）
   - 需要文件清单 + 职责 → 第二层（分支 `*/README.md`，先 Grep 命中相关行，再只读该段落）
   - 需要类/方法签名 → 第三层源文件 `.md`（当前仅 `backend/api/endpoints/torrent_crud.md` 有样例；其余直接读源码或用 Grep 提取）
4. **源码确认**：roadmap 行号可能与当前 HEAD 漂移，定位到文件后以源码实测为准。

## token 纪律

- 大文件禁止 Read 全文：先 `Grep <关键词>` 定位行号，再 `Read <文件> <起行>-<止行>` 精准片段。
- 目标明确时 2~3 次工具调用内应完成定位；超过即复查导航路径是否绕路。
- 记录读取日志（`READ|<文件>|<行范围>`），便于复盘成本。

## 分层速查（token 参考）

| 层级 | 内容 | 读取方式 | token 参考 |
|------|------|---------|-----------|
| 第一层 | 根 README：模块路由 + 功能域速查 + 分支说明 | Read 全文或 Grep 命中行 | 根全文 ≈2.8K |
| 第二层 | 分支 README：子分支索引 + 文件清单表 + 架构事实 | Grep 命中行 → 只读段落 | 单份 ≈1~3K |
| 第三层 | 源文件 .md：类/函数索引 + 方法签名 | Read 目标文件 | 样例 ≈4.6K |
| 源码 | 实际代码 | Grep + 片段 Read | 按需 |

## 与 code-graph 的取舍

- 定位**前端**代码：本技能（roadmap 覆盖前端视图索引）优于 code-graph（图谱不覆盖前端）。
- 定位**后端**类/方法签名：code-graph 微观图含签名但**图谱过时**（构建 2026-07-17）需源码核验；roadmap 索引准确但无第三层签名，需读源码。两者互补。

## 漂移提醒

- roadmap 元信息标注"行号依据：全部由当前源码实测，禁止沿用历史文档行号"——若源码与文档不符，以源码为准并更新 roadmap。
- 部分分支 README 标注"本次未产出第三层"，需源码兜底。

# Roadmap Maintain（roadmap 维护）

## 目的

源码变更后同步 `docs/roadmap/`，保持其为"对源码结构的有证据索引"。与 `roadmap-navigation`（读方向）互补，本技能负责**写入/维护**方向。

## 核心原则

1. **行号实测**：roadmap 元信息规定"行号依据：全部由当前源码 grep / Read 实测，禁止沿用历史文档行号"。任何行号/符号计数必须现测现写。
2. **单一真相**：架构论述、约束条款已在其他文档存在的，只放"索引 + 链接"，不复制全文。
3. **最小改动**：只更新受影响的条目，不重排/重写无关内容。
4. **以源码为准**：源码与文档漂移时，更新 roadmap 使其贴合源码，并在元信息或 risks 中标注。

## 三层维护范围

| 层 | 文件 | 维护点 |
|----|------|--------|
| 第一层 | `docs/roadmap/README.md` | 模块路由树、**功能域速查表**（新增功能 → 新增行）、分支说明表、元信息（生成日期/本次新增/覆盖深度） |
| 第二层 | `docs/roadmap/{backend,frontend,...}/*/README.md` | **关键词速查表**（新增/删除/改职责文件行）、详情表、架构事实/关键模式 |
| 第三层 | `docs/roadmap/**/endpoints/*.md` 等源文件 md | 类/函数索引 + 方法签名（当前仅 `backend/api/endpoints/torrent_crud.md` 有样例，按"模式 B"增量补齐） |

## 维护流程

1. **识别变更**：`git status` / `git diff` 或源码扫描，确定新增/删除/重命名/改行号的源文件。
2. **定位影响面**：用 `Grep -i <模块关键词> docs/roadmap/` 命中受影响的分支 README 与功能域速查行。
3. **实测行号**：`Grep -n` 或 Read 源码确认新行号/符号。
4. **更新条目**：
   - 新增文件 → 在对应分支 README 关键词速查 + 详情表加行；若属新功能域则根 README 功能域速查加行。
   - 删除/重命名文件 → 更新对应行。
   - 职责变更 → 精简改写"一句话职责"，保留版本标记（如 v1.0.6.37）。
   - 重命名分支/模块 → 更新根模块路由树 + 分支说明表。
5. **更新元信息**：根 README 元信息表的"生成日期 / 本次新增 / 覆盖深度"。
6. **校验**：改完 Grep 回读命中行，确认无遗漏、无格式破坏。

## 漂移检测

- 定位或更新时发现源码行号/结构与 roadmap 不符 → 立即按上文流程修正 roadmap。
- 版本类漂移（如代码已 v1.0.6.37 但 roadmap 只到 .36）→ 更新"本次新增"并补齐受影响条目。

## 与其他技能的关系

- **读方向**：`roadmap-navigation` 技能（定位/读取三层结构）。本技能只负责写入。
- **会话交接**：上下文压缩前的任务文档更新走 `dev-docs-update` command（`/dev/active/` 任务文档），本技能不覆盖该场景。

## token 纪律

- 更新时同样用 Grep 定位目标行后只 Read 受影响段落，不 Read 全文。
- 保持新增内容精简：一行一个模块，职责不超过一句话。
